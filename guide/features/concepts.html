核心概念

本章介绍 NucleusX-Core 的核心设计理念和架构思想。

设计理念

NucleusX-Core 的设计遵循以下几个核心理念：

业务逻辑去平台化

"业务逻辑应当是独立的、可移植的、长寿的。平台和 UI 框架只是阶段性的实现选择。"

NucleusX-Core 旨在让业务代码 经得起时间与平台变化的考验。

  • 业务代码不直接依赖小程序/H5/UI框架API
  • 通过统一的抽象层访问平台能力
  • 实现业务逻辑与平台实现的解耦

统一运行时上下文

提供统一的 API 访问接口，使业务逻辑能够：

  • 通过单一入口访问请求、状态、日志等能力
  • 在不同环境下保持一致的行为
  • 简化依赖管理和测试

可配置式集成

根据运行环境注入不同实现，无需修改业务代码：

  • 通过 Kit 配置不同平台的实现
  • 支持动态注入和替换底层实现
  • 保持业务逻辑的平台无关性

核心架构

Kit 模式

Kit（工具包）是 NucleusX-Core 的核心配置模式，它将所有平台特定的实现打包在一起：

interface IKit {
  platformBridge: IPlatformBridge;    // 平台桥接器
  storeEngine: StoreEngine;           // 状态管理引擎
  request: IRequestConfig;            // 请求配置
  router: IRouterConfig;              // 路由配置
  logger: ILoggerConfig;              // 日志配置
  appInfo?: IAppInfo;                 // 应用信息
}

依赖注入机制

NucleusX-Core 采用依赖注入模式管理各个模块：

  1. 注册阶段: 通过 createRuntime(kit) 注册所有实现
  2. 解析阶段: 运行时根据需要解析和注入依赖
  3. 使用阶段: 业务代码通过统一接口访问功能

虚拟路由引擎

NucleusX 的虚拟路由引擎是其最具创新性的部分：

  • 突破原生页面栈限制: 实现无限层级的路由跳转
  • SPA/MPA 混合模式: 支持多种导航模式
  • 权限治理: 内置 RBAC 权限控制

关键术语

PlatformBridge（平台桥接器）

平台桥接器是连接 NucleusX-Core 与具体平台的桥梁，它抽象了平台特定的 API：

  • 统一消息提示接口
  • 统一存储接口
  • 统一导航接口
  • 统一系统信息接口

StoreEngine（状态管理引擎）

状态管理引擎是状态管理的抽象层，支持多种底层实现：

  • 支持 Pinia（Vue 环境）
  • 支持 MobX（小程序环境）
  • 可扩展其他状态管理库

RequestAdapter（请求适配器）

请求适配器负责将统一的请求接口映射到底层平台的网络 API：

  • 小程序环境：wx.request
  • H5 环境：fetch 或 XMLHttpRequest
  • React Native：fetch 或第三方库

架构优势

1. 降低维护成本

通过抽象层隔离业务逻辑与平台实现，当平台 API 变更时只需修改适配器，而不需要修改业务代码。

2. 提高可测试性

依赖注入使得单元测试更容易，可以轻松模拟各种依赖。

3. 支持多端复用

同一套业务逻辑可以在不同平台运行，提高代码复用率。

4. 增强稳定性

通过防御性校验和统一的错误处理，减少运行时错误。

适用场景

适合使用

  • 企业级核心业务系统
  • 多端（小程序/H5/App）统一业务逻辑
  • 5人以上团队协作开发
  • 需要长期维护、持续迭代的产品
  • 对业务稳定性、可控性要求较高的系统

不适合使用

  • 一次性活动页/营销页
  • 极简工具类项目
  • 生命周期<3个月的实验性项目
  • 仅单端、无长期维护计划的应用

重要提醒: NucleusX 并非"开发提速工具"，而是"长期治理工具"。

商业考虑

  • ❌ 禁止：未授权的商业项目、生产环境使用
